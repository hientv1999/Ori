# Ori — Firmware

## Build System

- **IDE / build tool**: PlatformIO
- **Framework**: Arduino
- **Target board**: Waveshare ESP32-S3 Touch LCD 4.3" (ESP32-S3)
- **NimBLE persisted-CCCD store is GLOBAL, not per-peer**: `CONFIG_BT_NIMBLE_MAX_CCCDS` (`platformio.ini`, set to 24; NimBLE default 8) caps persisted subscription records across BOTH bonded peers. On overflow NimBLE silently **unpairs the oldest bonded peer** — deletes its LTK and terminates its live link (killed the Orion bond whenever the iPhone paired, 2026-07). Every new notify characteristic Orion subscribes to consumes one slot; keep the cap ≥ total subscriptions across both peers + headroom.
- **A bonded reconnect auto-fires `onSubscribe()` from NimBLE's OWN bond-store restore, not from anything the central does.** `ble_gatts_bonding_restored()` (`nimble/host/src/ble_gatts.c`, on encryption-restored) reads every persisted CCCD and re-fires `onSubscribe()` server-side — near-instantaneous, often before Orion has even finished GATT discovery. For a notify-only characteristic whose only backfill is an `onSubscribe()`-triggered resync (chars 0010/0011, `ble-protocol.md` §13), **the central cannot reliably win this race no matter how early it subscribes** — confirmed on hardware: Ori's resync landed correctly while Orion's receiver, created as early as possible, still wasn't alive; the burst was silently lost. **Fix belongs on the firmware side:** `state_machine::on_reconnect_end()` (fires only on a genuine reconnect's `SyncEnd`, causally guaranteed after Orion has subscribed — full writeup in `pc-app.md`) calls `ancs_client::resync_orion_relay()`/`resync_orion_call_state()` a second, unconditional time. Both are idempotent, so the redundant second firing is a harmless refresh.
- **Every NOTIFY characteristic must ALSO declare `NIMBLE_PROPERTY::READ`** (see 0001/000A/000F/0010/0011 in `gatt_server.cpp`). Windows' WinRT GATT stack silently delivers no notifications for a characteristic lacking base READ, while `subscribe()`/CCCD-write still report success — an invisible failure. Cost 2026-07: chars 000A/0010/0011 lacked it and every ANCS relay notification was dropped before reaching Orion. Keep `READ` alongside `READ_AUTHEN` (MITM-gated) on all notify chars; never "tighten" one to notify-only. Full write-up: `ble-protocol.md` §3.
- **`NimBLEAdvertising::reset()` clears advertising data ONLY IF its internal `stop()` call succeeds** (a failed `stop()` short-circuits, silently skipping the payload clear). In `ble_manager.cpp::restart_advertising()`, advertising is already stopped earlier in the function, so `reset()`'s own `stop()` reliably fails and the payload never clears. Compounded by `NimBLEAdvertisementData::addServiceUUID()` having no dedup — a repeat call just appends another 16 bytes. Net effect (found 2026-07): every `restart_advertising()` call grew the Ori Sync UUID field until it exceeded the 31-byte legacy adv PDU cap, desyncing the NimBLE host enough to also break encryption/auth for both peers. **Fix: call `adv->clearData()` instead of `adv->reset()`** — no `stop()` dependency, no failure path, unconditionally wipes `m_advData`/`m_scanData` every call.

## What the Firmware Must Implement

- **Display**: 800 × 480 UI — `screen-layout.md`, `state-machine.md`
- **Touch**: GT911 driver; single-touch UI interactions — `gestures.md`
- **BLE — PC link**: Orion sync (profile, calendar, Time Off, time, backlight, factory reset) — `connectivity.md`, `ble-protocol.md`
- **BLE — Phone link**: ANCS client — bonds with an iPhone *or* iPad (same GATT surface, one code path, `connectivity.md` §2) — notification icons in status bar; tap opens detail overlay (title + body); read-only — `connectivity.md`. Icon registry (`ancs_icons.h/cpp`): compiled-in token→colour+image table for 57 apps. **Adding a new app icon requires a firmware update.** Supported tokens: `gmail`, `messenger`, `instagram`, `facebook`, `whatsapp`, `slack`, `twitter`, `teams`, `sms`, `phone`, `discord`, `telegram`, `youtube`, `youtube_music`, `tiktok`, `spotify`, `wechat`, `line`, `zoom`, `outlook`, `snapchat`, `google_meet`, `facetime`, `linkedin`, `reddit`, `threads`, `twitch`, `uber`, `apple_music`, `amazon`, `viber`, `claude`, `chatgpt`, `google_map`, `google_photos`, `health`, `apple_calendar`, `apple_findmy`, `apple_mail`, `apple_maps`, `apple_reminders`, `apple_wallet`, `github`, `google_authenticator`, `microsoft_authenticator`, `notion`, `venmo`, `skype`, `paypal`, `wealthsimple`, `zalo`, `td`, `bmo`, `rbc`, `scotiabank`, `cibc`, `apple_settings`. Unknown tokens fall back to a brand-colour circle, and `ancs_client` logs `[ancs] unmapped app bundle=<id>` the first time a notification arrives from an app with no `ancs_bundle_map.cpp` row — which is how an unverified bundle ID gets corrected without guesswork. The same token vocabulary doubles as the **AppPassthrough allowlist** (ANCS filter level 3, char `0016`): Orion sends the tokens the user picked, Ori stores them packed in NVS (`nvs::get/set_ancs_apps`) and `ancs_client::passes_filter()` matches an incoming notification's own token against them — calls always pass, as at every level except Disabled. On connect Ori also reads the bonded device's GAP Device Name (unpair modal), its Model Number String (`iphone_model_map.h`, resolved to a marketing name and to the "iPhone"/"iPad" word `ancs_client::phone_kind_word()` puts in UI text), and its **Current Time Service** (0x1805) as a **secondary** clock source — used only when Orion (primary) hasn't set the time; see `connectivity.md`.
- **Controls-mode BLE chars** (chars 10–13, no HOGP): `Keyboard Command` (notify P→C; internal name kept for historical reasons), `Host Volume State`, `Media Metadata`, `Media Album Art` (chunked JPEG) — `ble-protocol.md` §3, §12
- **Connection status border**: profile-photo border/glow reflects Ori's own BLE connection state to Orion (Device Status — connected/reconnecting-syncing/disconnected), derived entirely on-device, not pushed by Orion. Handler → `widget_profile_card::set_conn_status()` → `theme::COLOR_CONN_*`. Updated wherever Device Status transitions between `RUNTIME_READY`/`RUNTIME_RECONNECTING`/`RUNTIME_SYNCING`/disconnected already happen in `state_machine.cpp`/`ble_manager.cpp`. Colour map: `screen-layout.md`
- **Controls-mode UI** (internal: `kbd-mode`): 484 × 216 album-art image with touch-revealed transport controls, title + artist, three shortcut buttons — full gesture set in `media-mode.md`. Empty state: Ori wordmark on dark gradient. JPEG decoder: `LV_USE_TJPGD`. Mode persists in NVS. Shortcut button icons are compiled-in flash assets; **adding new icon types requires a firmware update** — `media-mode.md`
- **Mode-toggle visibility**: show only once Orion has fully synced (`state_machine::set_pc_synced()`, called from `handle_sync_end()` on a real `SyncControl{END}`) — not merely BLE-connected (`set_pc_connected()`, which fires immediately on encryption complete, well before a reconnect's resync finishes). On PC link drop: remove toggle + auto-revert to calendar. On reconnect: toggle stays hidden through the RECONNECTING/SYNCING window and reappears only once resynced (calendar mode — entering Controls is always the user's explicit choice)
- **State machine**: priority-ordered left panel — `state-machine.md`
- **Meeting list**: sorting, overlap display, live expiry — `meeting-list.md`
- **NVS persistence**: profile, Time Off, backlight state, pairing bonds — survives power cycles. **Meeting list and local time are RAM-only** (deliberately not persisted) — re-synced from Orion on reconnect; see `meeting-list.md`. **Serial number + manufacture date live in a separate "factory" NVS partition**, read-only at runtime (`factory_info.h`) and untouched by `nvs::factory_reset()` — survives both a factory reset and a firmware update by construction; see `provisioning.md`.
- **Backlight**: always ON — set by `backlight::init()` at boot via CH422G EXIO2; no runtime control
- **Setup flow**: first-boot sequence, factory reset — `setup-flow.md`
- **5-minute alert timer**: countdown modal before each meeting — `state-machine.md`
- **Firmware update receiver**: **BLE only** — chars `0014`/`0015` on the Ori Sync Service (`ble-protocol.md` §14), Orion-bond-gated. The USB CDC path was deleted 2026-08-16 (no reachable data port on a deployed unit); do not reintroduce one. Stages the whole image in PSRAM, verifies SHA-256 + the embedded `OriFwVer=` marker, then feeds the Arduino `Update` library into the inactive OTA slot in one burst; bootloader rollback on unhealthy first boot. `VALIDATED` is notified **before** the commit, because the commit deinits NimBLE. Bricked-unit recovery: internal UART (service path only, enclosure required) — now the *only* way back from a build that boots but can't do BLE, so treat "BLE comes up and Orion connects" as a release-blocking smoke test. Receiver `src/ota_receiver.cpp`, screen `src/screens/screen_ota_updating.cpp` — `ota.md`
  - **Threading rule:** the char `0014`/`0015` write callbacks run on the NimBLE host task and may only do pure computation, memcpy into the already-allocated PSRAM staging buffer, and send notifies. PSRAM allocation, the SHA-256 pass, LVGL, and NVS are all deferred to `ota_receiver::poll()` on the main task via `FwUpdateBegin`/`FwUpdateEnd`/`FwUpdateAbort` on the existing BLE event queue.

### Adding an ANCS app icon

Drop `<token>.png` in `firmware/img/ANCS_icons/`, then:

1. `python convert_icons.py` — resizes to 60×60 and emits `src/assets/ancs_<token>.c` as ARGB8888. It processes **every** PNG in the folder, which would revert the whole set to ARGB8888; to add one icon, import the module and call `resize()`/`convert()` for just that file.
2. Add the token to `TOKENS` in `convert_ancs_indexed.py`, then run it — re-encodes to indexed I1/I2/I4/I8 (roughly a 68% cut) and **skips anything already indexed**, so a re-run is safe.
3. Register in three places: `extern` + `k_table` (brand colour) + `k_images` in `src/assets/ancs_icons.cpp`, and the iOS bundle ID in `src/ble/ancs_bundle_map.cpp` — **without the bundle-map row the icon is dead code**, since ANCS only ever hands over an AppIdentifier.
4. Orion needs the same PNG (`cropped/<token>.png` → `../Orion/src/assets/ancs_icons/`) plus a row in `ANCS_APP_ICON_MAP` — the filter picker and the notification list both key off that map.

Fixed 2026-09-04: `convert_ancs_indexed.py`'s already-indexed check grepped for the bare word `ARGB8888`, which its own output header contains ("Re-encoded from ARGB8888 to …"), so it never skipped and died on the first token. It now keys on the `.cf = LV_COLOR_FORMAT_ARGB8888` descriptor field. The same run also caught `youtube_music`, left un-indexed for the same reason.

## LVGL Rendering Rules

- **All circular progress rings sweep clockwise** — countdown modal, OTA ring, reconnect-syncing overlay, setup spinners (Steps 2/3/4), re-pair phone spinner, and any future progress visual. In LVGL, ensure the arc end-angle increases in the direction of clock motion (LVGL 0° = 3 o'clock, angle increases clockwise). Counter-clockwise is banned.

- **Pressed-state feedback: use `lv_obj_set_style_opa`, not style transitions** — animating `LV_STYLE_BG_OPA`, `LV_STYLE_SHADOW_WIDTH`, or `LV_STYLE_SHADOW_SPREAD` via `lv_style_transition_dsc_t` causes a brief black flash on label text mid-animation (LVGL composites the button interior against near-black before reblending children). Use `lv_obj_set_style_opa(widget, LV_OPA_60, LV_STATE_PRESSED)` — no transition, no animation. Applied globally in `ui_helpers.cpp::make_btn()` and all interactive widgets.
